## 1. Root cause (Phase 1 — measured, with file/line evidence)

For mission document/website builds the **hosted self-verifier audited the assistant's file-fenced reply wrapper, not the deliverable**:

1. `runGiftzTurnCore` ran `verifyAndCorrect(originalRequest, draft=<raw reply>)` **before** `parseFiles`/`applyFiles` persisted anything (`src/lib/giftz/turn.ts`). No persisted-file evidence existed at audit time.
2. `buildVerifierUserTurn` truncated the draft at `maxInputChars/2` (15,000 chars default). Multi-file website wrappers arrive mid-file-cut; complete documents arrive as fence syntax the verifier grades as broken code.
3. The verdict (`unverified`/`corrected-unverified`) failed the mission gate's `requireSelfVerification` check → bounded correction round repeated the **identical wrapper audit** → budgets exhausted → task failed → mission failed. M41.5 evidence rows 18/3/5 FAIL + 16 honest-unavailable.

The deterministic mission verifier never inspected the persisted deliverable either: documents were verified by proxy (path name in `changes[]` + `contentChars ≥ 400`), websites had no persisted-structure checks at all.

## 2. The repair (Phases 2–5) — same architecture, honest targets

**No second verifier architecture.** The SAME hosted pipeline (`verifyAndCorrect`), the SAME bounds, the SAME honesty outcomes — only the audited input and the evidence changed:

- **`mission/verify-context.ts` (new, pure)** — the trusted, system-authored `MissionVerificationContext` (ids, deliverable kind/path, required paths/sections, citation contract, the EXACT numbered handed-off sources via `handoffSourceRefs` — numbering identical to the handoff pack), bounded serialization, and a shape-checked worker-side parser whose malformed input can only *disable* the mission framing, never weaken a gate. `buildDeliverableAuditInput` turns the EXTRACTED files into the verifier's audit input (wrapper prose and fences structurally excluded; explicit file-inventory anchor; honest NO-DELIVERABLE text when nothing parsed). `buildMissionAuditRequest` frames the acceptance contract plus DETERMINISTIC PRE-CHECKS (mechanically settled facts the audit must not re-litigate).
- **Threading** — the mission executor builds the context from the mission ledger and passes it through a THIRD server-only parameter of `submitCodingDelegation` (`validateDelegateCodingInput` has no mission field — the model-called tool structurally cannot attach or alter its own verification framing) → job `paramsJson` → `giftz-coding-handler` → `runGiftzTurnCore(input.mission)`. The job result carries an honest `verificationSkippedReason` (operator-disabled vs missing evidence).
- **Turn core mission branch** — generation → `parseFiles` → hosted `verifyAndCorrect` over the deliverable audit input; a corrective revision regenerates the FULL wrapper via the existing streaming/buffered paths, re-extracts and re-audits; the persisted reply stays the conversational answer. Non-mission turns remain byte-identical wrapper audits.
- **Deterministic persisted-deliverable verification** — the executor loads the project-scoped `CodeFile` snapshot (`loadPersistedDeliverable`; only the delegation's own project; bounded) and the pure verifiers audit REAL persisted files:
  - `verifyDocumentDraft`: the ten Phase-3 checks — (1) required file exists, (2) path safety/authorized boundary, (3) non-empty within limits, (4) markdown structure, (5) required sections (`Sources`), (6) numbered citations present (cluster styles `[1, 4]` and bounded ranges `[1-3]` parse — live-measured), (7) markers correspond to the handed-off sources, (8) out-of-pack URLs named and refused, (9) malformed/missing source refs fail, (10) unclosed-fence truncation cannot pass. Legacy no-snapshot path keeps the original proxy contract.
  - `verifyWebsiteBuild` (new): static sites audited AS static sites by reusing the existing `auditPreview` auditor — required entry files exist with substantive content, internal links/assets resolve, no empty files, **no package.json demand**; HTML files alone never verify.
  - Planner emits `deliverableKind`/`requiredPaths`/`requiredSections` per mission shape; `buildTaskSpec` normalizes criteria and structurally refuses contradictory kinds and unsafe paths.
- **Durability closure (live-found)** — `settleOrphanedRunningMissions()`: a mission whose DRIVER job died terminally mid-run (repeated worker loss) stayed `running` forever; the riishe pool's maintenance loop now sweeps orphans and settles them with deadline semantics (CAS-guarded, Trust failed).
- **Security unchanged (Phase 5)** — criteria live in the mission ledger only (a specialist cannot rewrite its own acceptance contract); paths project-scoped + traversal-checked; context data is `safeSourceUrl`'d public research metadata (no secrets); two-key delegation and hosted-verifier participation intact — a failed hosted audit still blocks; an absent snapshot is `needs_correction`, never a pass.
