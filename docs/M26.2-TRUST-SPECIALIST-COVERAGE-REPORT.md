## 2. Key design decisions

- **Scene jobs record no standalone receipt.** A director scene job's failure/cancellation is already carried by its production's orchestration receipt (failed scenes → limitations / partial outcome; cancel → cancelled production with preserved scenes). A second per-scene receipt would duplicate, not add coverage. `isDirectorSceneJob()` gates the standalone media receipts.
- **Idempotent settlement (media adapter).** Every `recordMediaJob*` checks for an existing receipt task for the same `jobId` first: a terminal task ⇒ the late event is a no-op; concurrent workers can never settle one job into two receipts.
- **Truthful mutation accounting for CODE GIFTZ.** `applyFiles` is per-file, not transactional. It now wraps failures in `WorkspaceApplyError` carrying `appliedSoFar` + `failedPath`, so a receipt can (a) state "no workspace changes were applied" ONLY when the failure happened before the apply stage, and (b) record the mutations that DID land when it failed mid-apply. Cancellation observed after a successful turn records the applied mutations in the cancel note — cancellation never erases them, and the unpersisted reply is stated.
- **Never-pretend preservation (LAXII).** The preservation report is recorded as measured facts (`exactPreservedPct`, `changedPct`, `generativeUsed`) with the explicit sentence that it is NOT an aesthetic-quality claim. A whole-image hosted edit (no preservation applies) settles `completed_with_limitations` with an explicit no-verification limitation. Dimension drift and a failed identity metric are limitations, never hidden.
- **Unverified coding turns never settle plain completed.** Background turns whose self-verification was disabled or inconclusive settle `completed_with_limitations`; the receipt always states that project build/tests were not run by the turn.
- **No stuck running receipts.** `processProductionJob` settles its Trust task failed on an unexpected throw before rethrowing (the runner still settles the job row). Pre-plan failures (PLAN_MISSING / PLAN_INVALID) and orphan jobs (PARAMS_INVALID / PRODUCTION_NOT_FOUND) create minimal honest receipts instead of staying silent.
- **Lifecycle states unchanged.** The honest mapping uses the EXISTING states only: completed / completed_with_limitations / partially_completed / failed / cancelled / waiting_for_approval. No new state names were introduced.

- GANGZII audio tasks have no execution handler (NO_BACKEND) — nothing is performed, so nothing is receipted.
